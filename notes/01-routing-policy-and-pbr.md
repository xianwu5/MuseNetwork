# 知识点：路由策略与策略路由

日期：2026-11-04
所属月份/阶段：第 1 个月 / 路由进阶

## 核心概念

一句话区分：

- 路由策略：控制路由本身。决定路由表里有什么、学不学某条路由、选哪条路由。
- 策略路由（PBR）：控制数据包怎么走。路由表已经有了，但按源地址、业务等条件，强制数据包走另一条路。

## 路由策略

作用在控制面，发生在路由生成、接收、发布和选路阶段。

常用工具：

- 前缀列表（prefix-list）：按网段精确匹配
- AS 路径列表、团体属性（Community）
- route-map：匹配条件 + 执行动作，带序号，permit / deny
- 导入、导出策略：import / export、filter-policy

常用动作：

- 过滤路由：不接收、不发布某条路由，防止路由泄露
- 改属性调选路：BGP 的 Local Preference、MED、AS_PATH，OSPF 的 Cost
- 路由汇总、打标签（Tag）

典型场景：多出口选路调优、不同部门或分支只放行需要的路由、防止私网路由外泄。

## 策略路由（PBR）

作用在转发面，不改路由表。数据包到了接口，先按策略匹配，再决定下一跳。

匹配条件通常是 ACL：源地址、目的地址、协议、端口，有时还有报文长度。

执行动作：

- set ip next-hop：强制下一跳
- set interface：强制出接口
- set ip default next-hop：只有路由表里没有匹配路由时才生效

注意点：

- 一般应用在接口入方向；设备自己产生的流量要用 local PBR。
- PBR 优先级高于普通路由表，配错容易绕过正常选路，造成环路或不对称路由。
- 下一跳失效要有回退：配合 track / verify-availability，否则会黑洞；或者用 default next-hop 做兜底。
- 和 NAT、VPN、防火墙的配合顺序要先确认，PBR 位置不同结果可能不同。

## 路由策略 vs 策略路由

- 作用对象：路由策略针对路由，策略路由针对数据包
- 作用阶段：路由策略在路由表形成之前，策略路由在查表转发时
- 是否改路由表：路由策略会改，策略路由不会
- 排障看什么：路由策略看路由表和策略匹配，策略路由看接口策略、下一跳状态和实际转发路径

## 企业网 / 园区网例子

- 办公流量走电信出口，视频会议走联通出口：用 PBR 按源网段或业务分流。
- 希望某条 BGP 前缀优先从某个邻居学习：用路由策略改 Local Preference。
- 访客网只能上互联网、不能进内网：PBR 强制走互联网出口，同时用 ACL 或路由过滤兜底。

## 排障思路

- 先确认是路由问题还是转发问题：查路由表，再查接口 PBR。
- route-map 序号从小到大匹配，注意最后的隐含 deny 和空匹配条件。
- PBR 不生效：先看策略是否应用在正确的接口和方向，再看 ACL 是否命中、下一跳是否可达。
- 流量走了预期之外的路：先查 PBR，再查路由表，最后查 NAT / 策略的叠加影响。
